# PB-10 — Complete diagnostic evidence and signing
Owner A. Input is authoritative stored inventory, manifest, scope plus PB-08/PB-09 results. Output is a complete ordered report and separate-domain EIP-712 diagnostic attestation.

Reject missing/duplicate deployments, incomplete/duplicate assertions, mixed snapshots, mismatched document hashes, invalid scope identity, changed test packs, stale/future timestamps and evaluator mismatch. All implementation/path/authority/configuration prerequisites are combined into the required `configuration` assertion; detailed observations remain in the report. A failed prerequisite cannot be hidden by two passing behavioral tests. Preview never becomes a deployed pass. Diagnostic reports are explicitly not financial receipts and carry `claimEligible:false`.

`signEvidence` rebuilds coverage before signing; `verifySignedEvidence` requires the caller's independently trusted scope, verifies freshness/signature, and rebuilds the summary. Signature proves the named evaluator attested, not that it was honest or that RPC state was independently proven. A passing report describes this fixed test pack, not universal security.

`loadEvidenceSigner` requires a dedicated unfunded verifier key in an owner-readable-only regular file, rejects symlinks and mismatched public address. The API has only the public evaluator address. Signing occurs in the trusted host worker; the key never enters the sandbox or child environment. No supplier/customer wallet is used. Production remote signing/HSM and campaign receipt creation remain integration work; key rotation requires a newly approved scope.

Validation: `pnpm check`, including five structural/cryptographic evidence cases and one real filesystem key-permission case. Those unit reports are explicitly synthetic test inputs; PB-11 supplies actual inspection/execution results end to end. Existing TS/Solidity financial receipt types/vectors are unchanged.
