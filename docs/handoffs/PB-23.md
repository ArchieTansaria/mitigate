# PB-23 handoff — backend security and outage checks

**Status:** partial local outage coverage added; cross-chain and indexer/reorg cases remain blocked by PB-21/22 integration inputs.

## Implemented coverage

`tests/integration/security-outages.test.ts` uses PostgreSQL, a local Anvil source chain, the real Fastify API, real wallet signatures and the filesystem artifact store. It verifies:

- A queued diagnostic remains queued after the API restarts while no worker is running. The API does not attribute the outage to the supplier or expose claim eligibility.
- If stored evidence disappears, `GET /v1/runs/:id/evidence` returns `503 ARTIFACT_UNAVAILABLE_OR_CORRUPT`; the job status remains `succeeded` but reports only that an evidence reference is stored and that repair outcome was not evaluated by the API.
- If the source RPC is unreachable during wallet verification, the API returns `503 RPC_UNAVAILABLE` and creates no authenticated session.

The shared `RunStatusSchema` and generated OpenAPI route responses now use `evidenceReferenceStored` and `repairOutcome: not-evaluated`. A stored artifact reference no longer gets described as an available report or repair result.

## Validation

After removing generated `contracts/out` and `contracts/cache` artifacts, the targeted command is:

```sh
pnpm test:integration tests/integration/security-outages.test.ts
```

`pnpm test:integration tests/integration/security-outages.test.ts` passed: 1 file, 3 tests. It builds only the PB-03 `EncodingHarness` artifact required by integration tests before running Vitest.

The full command `pnpm test:integration` passed: 12 files, 41 tests. `pnpm lint`, `pnpm typecheck`, `pnpm typecheck:cre`, and `pnpm test` also passed; the unit run reported 15 files and 73 tests. The full `pnpm check` did not pass because its Foundry contract stage traps in the pinned solc-js compiler under Node 24.1.0 while compiling 81 files; see `docs/handoffs/PB-22.md` for the exact failure. These results do not replace B's Studio verification or live route evidence.

Existing tests also cover wallet nonce replay, cross-tenant run/evidence access, malformed/URL-shaped manifest input, content corruption and bounded PB-19 challenge/review-timeout accounting. The full integration suite and Foundry results are recorded separately from these focused checks.

## Remaining PB-23 gaps

- CRE and CCIP outages cannot be injected into a product acceptance route: PB-21 does not issue receipts or deliver reports, and PB-22 has no campaign indexer/API yet.
- Reorg rollback and observed-versus-current campaign configuration cannot be tested before PB-22's indexer, generated ABIs and deployment manifest exist.
- No two-machine reproduction was run. Contract-side direct challenge and timeout exits are covered by PB-19 Foundry tests, but the complete suite could not be reproduced in this Node 24.1.0 checkout because the pinned solc-js compiler traps while compiling 81 files.

Unavailable verification remains unassessed. It must not become a failed repair, failed claim, or supplier-attributed outcome.
