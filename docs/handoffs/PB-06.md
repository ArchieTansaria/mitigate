# PB-06 — Authenticated diagnostic API

Working Fastify server with generated OpenAPI, SIWE challenges, atomic single-use nonce consumption, random expiring Bearer sessions hashed at rest, and explicit tenant-owned inventory/manifest/scope/run endpoints. Auth verifies EOAs or deployed EIP-1271 contract wallets through the configured source chain. Counterfactual wallet deployment is unsupported. A session never authorizes an onchain state change.

Scope creation pins input digests, evaluator and freshness settings; runs must reference that exact owned scope. No arbitrary URL fetches, uploaded executables, user-specified RPCs or public mark-pass endpoint exist. Campaign runs are explicitly rejected until financial/receipt integration. Uploaded artifact references are stored as data, never fetched/executed here.

Private evidence is available only to its owner after processing. Owner-consented diagnostic publication is a separate endpoint; public access cannot enumerate private inventories/scopes. Initial publication is irreversible. Request/socket timeouts, a shutdown deadline, exact trusted-proxy configuration and independent health checks avoid the reviewed resource failures.

Validation: actual PostgreSQL auth/API tests; nonce replay/expiry/domain/signer tampering, cross-tenant access, idempotency, quotas, body/content limits and explicit publication. Actual EIP-1271 test contract deployed on local Anvil, plus negative unsupported/RPC tests. A separate API process serves HTTP health/OpenAPI and terminates with an unfinished request. Proxy tests distinguish trusted and forged forwarding headers.

Start and limitations: docs/runbooks/backend-start.md. This batch has no repair consumer: queued requests will not execute until PB-08–11. PublicJob deliberately does not infer a repair pass from processing status. No live grant, CRE report callback, hosted S3 or testnet fixture deployment is claimed.
