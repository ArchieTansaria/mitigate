# PB-25 — Orryn verification workspace

Updated 2026-11-07. Owner A. User explicitly requested frontend implementation before PB-24 completion; the live integration gate is still open.

## Implemented
- Next.js/Tailwind dark/orange Orryn workspace: overview, run history, inventory wizard, release manifests, evidence detail, settings and public reports. Public landing uses the corrected Orryn brand.
- Wallet connect and separate SIWE authentication; account/network changes invalidate the session. Server-side allowlisted API bridge uses bounded requests, HttpOnly same-site cookies and mutation-origin checks. No API bearer token or wallet key in browser storage.
- Validated manifest and inventory → backend registration → scope → diagnostic queue. Stable idempotency key on unchanged retries. Recent-run references are browser-local and account-specific; status and evidence come from the API.
- Evidence separates job completion, assertion outcome, coverage, freshness and signature validity. Browser checks raw canonical content commitments and recovered EIP-712 signer. This does not prove evaluator honesty or independently replay tests.
- Private reports require authentication. Publication is explicit; published reports have `/reports/[id]` URLs and original JSON downloads.
- Missing API/configuration and malformed data show unavailable/error states. No sample balances, fake jobs or manufactured pass states.
