# PB-21 handoff — scoped CRE evidence evaluation

**Status:** local evaluator slice and CRE CLI compilation implemented; product receipt issuance, CLI simulation and live delivery are incomplete.

The PB-21 feature note already exists at `memory/features/19-product-cre-evidence-evaluation.md`; it is indexed in `memory/features/INDEX.md`. No duplicate note is needed.

## Behavior

`workflows/cre/src/main.ts` fetches an immutable artifact through CRE HTTP consensus, checks its content digest and size, verifies the PB-10 evaluator attestation, and validates shared PB-03/PB-14 policy, evidence and coverage schemas. It requires campaign-claim purpose, deployed mode, current unexpired evidence, exact policy/test-pack/scope hashes, complete unique deployment and mandatory assertion coverage, recipient-bound eligibility and registration, and matching source snapshot facts. Source and destination reads use finalized heights; campaign active state, campaign/registry policy hashes and registered recipient are checked against the PB-15/PB-17 reads. Failures stop the workflow. There is no alternate endpoint or mock fallback. Pure evidence evaluation now lives in `workflows/cre/src/evaluator.ts`, outside the WASM entry point.

The resulting report is an evidence-evaluation result only and always has `settlementEligible: false`. It does not sign `AcceptanceReceipt`, call the PB-16 verifier, submit a forwarder report, or send a CCIP message.

## Existing interface gap

- PB-10's production producer accepts only `purpose: diagnostic`; `buildEvidence` rejects campaign-claim purpose. Diagnostic evidence cannot qualify for payment, and this workflow rejects it.
- PB-16 freezes the `AcceptanceReceipt` and onchain validation interface, but the corresponding A-side campaign receipt producer/signing path is absent in this checkout. CRE has no authorized signing key in its config.
- Local PB-20 sender/receiver contracts and simulation tests are now present in `contracts/pb20/messaging/` and `contracts/test/pb20/`, documented in `docs/handoffs/PB-20.md`. They do not consume this PB-21 evaluation report or create a receipt; Studio build and live CCIP delivery remain unverified. No report delivery or receiver state can be claimed.
- `workflows/cre` has `workflow.yaml`, `project.yaml`, and a clearly non-runnable `config.example.json` using public testnet RPC endpoints. These enable CRE CLI compilation, but the template has no real campaign config and is not valid for a run or broadcast.

These gaps are why the local evaluator remains non-settlement. Resolve the evidence producer/signing boundary with the owner of the shared verifier interface, then integrate the exact PB-20 forwarder/receiver ABI and immutable deployment configuration. Do not change PB-03/PB-16 interfaces silently.
