There is no change to the frozen shared ABI.

OZ **5.4.0** transparent proxies create separate **ProxyAdmin contracts**; the supplier owns each ProxyAdmin and the source. The customer owns adapter configuration and the market. Supplier EOAs are not themselves proxy admin addresses. Unauthorized upgrades, source mutation and customer configuration changes revert. Both implementation initializers are disabled; proxies initialize atomically with nonzero customer, deployed source, positive age and supported exponent. Upgrade needs no reinitializer and preserves non-default source, max age, decimals, customer and paused market state.

V1's deliberate defect is specifically the missing `maxAge` enforcement. V2 adds exact `StalePrice(updatedAt,maxAge)` rejection after common zero-price/zero-timestamp/future-timestamp checks. An age equal to the limit is valid; limit + 1 is rejected. RiverMarket uses full-precision `mulDiv`, supports legitimate fresh quotes, and rounds down. With 3e18 collateral and a 2000e8 price, the independently expected value is 6000e18. Six-decimal misconfiguration produces 600000e18 and must fail the pack even though stale rejection succeeds.

The pack requires configuration, positive operation and exact stale rejection together. A paused market or unrelated revert cannot satisfy stale rejection; missing contracts/ABI data cannot produce success. Wrong feed, permissive age and decimals drift are explicitly tested. Source interventions are artificial and must stay on isolated forks/snapshots; the README defines reset requirements. Parent approval is still required before pinning this candidate pack into any campaign policy.

## Evidence boundary and remaining work

`fixtures/generated/run-*/manifest.json` is generated only after successful receipt status, creation-address checks, code reads, ERC-1967 implementation/admin slots, mined AdminChanged event, owner/configuration reads at a single block and snapshot-hash consistency. Approved implementation runtime is checked against the actual compiled artifact. The manifest contains real transaction objects, receipts, runtime bytecode and hashes. Numeric blockchain values use decimal strings; hashes use keccak256. Canonical JSON files use RFC 8785. `repair-N.json` is validated with the shared ManifestSchema and contains actual V2 address/hash and per-instance configuration predicates. ABI JSON and the copied test-pack/index are content-hashed. Simulation addresses are kept separately in `address-map.simulation.json` and are not accepted as evidence alone.

Generated runs are ignored and never seed a verifier result. Failed runs can leave partial folders without a final manifest. The output explicitly says `executionKind:local-anvil`, `claimEligible:false`; it has no acceptance assertion or signed receipt. The launcher creates its own fresh unforked loopback Anvil, uses unlocked local accounts, strips inherited RPC/signing settings, and does not accept remote RPCs, keys or fork parameters. No private key is read or exported; no external chain transaction is sent. Default execution stops the chain, so saved artifacts prove only that local run and are no longer queryable unless `--keep-alive` is used. Timestamp/compiler-metadata differences can change hashes on reproduction.

Limits: quote-only model, no actual borrowing/custody/debt engine; artificial owner-controlled source; no generic proxy support, generic storage-compatibility certification or production-security claim. Supplier upgrade authority can install arbitrary code, including code that overrides customer ownership; role separation describes this pinned implementation's controls, not protection against a malicious upgrade. No Sepolia/Arc deployment or Studio mutation was needed/performed. PB-08/PB-09 still own inspection, full snapshot-bound scenario orchestration and evidence/receipt integration. Parent owns package-script wiring, planning updates, review and commit.
