# PB-02 — bounded historical RPC and worker feasibility

Implemented: services/verifier/src/probe.ts, runtime.ts, probe-cli.ts. Tests cover wrong chain, missing block, reorg, confirmations, missing code, slow/oversized RPC, process timeout, output flooding and secret-free subprocess environment.

`probeSnapshot` receives explicit RPC configuration, chain, numeric block, contract, storage slot and limits. It resolves number/hash, checks confirmations, checks hash lookup, reads code/storage using EIP-1898 `{blockHash, requireCanonical:true}`, then rechecks canonical number/hash. Unsupported calls/provider failures return **unknown**, never repair pass. The configured RPC remains a trusted observation source; the probe is not a consensus proof or a vulnerability test.

Real evidence: docs/evidence/pb02-public-rpc.json. Both Arc testnet and Sepolia historical reads passed; Arc USDC decimals() returned 6. scripts/probe-public-rpc.ts reproduces these read-only checks, using a public Sepolia provider or SEPOLIA_RPC_URL. It does not broadcast transactions. Public RPCs may rate limit or lack old history; the recorded success covers only the recorded blocks.

`probeContainer` runs actual Foundry in a digest-pinned image: unprivileged user, no network, read-only root, no extra capabilities, no new privileges, bounded memory/CPU/PIDs/tmpfs. Child processes have timeout and output limits and receive no inherited secrets. The container is explicitly removed after execution. Integration tests test actual filesystem/network/user isolation. No arbitrary uploaded test code is accepted.

Commands:
- `pnpm test` — local RPC-server/process tests.
- `pnpm test:integration` — actual Anvil historical reads, hash parity and Docker isolation (Docker/image required; see docs/toolchain.md).
- `node scripts/probe-public-rpc.ts` — real read-only network probes.
- `pnpm probe:rpc` with PROBE_RPC_URL, PROBE_CHAIN_ID, PROBE_BLOCK_NUMBER, PROBE_ADDRESS, PROBE_STORAGE_SLOT and PROBE_CONFIRMATIONS — custom administrative probe; optional PROBE_TIMEOUT_MS.

This is the runtime prerequisite, not PB-09's repair test runner. The eventual worker needs preloaded test packs/compiler and a separate controlled RPC input boundary; the current networkless container cannot fetch arbitrary source state. No acceptance receipt is issued by a probe.
