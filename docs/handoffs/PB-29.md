# PB-29 — Orynn public landing page

## Result

Converted the supplied Stitch landing page into `apps/web`, a standalone Next.js App Router and Tailwind CSS 4 workspace package. The website is public and read-only. It presents the product problem, supplier/customer workflow, supported prototype boundary, and source-chain → verifier → Arc architecture.

Implemented in commit `f1dece3` (`feat(web): add Orynn public landing page [PB-29]`), pushed to `main`.

The original export remains at `stitch_design/landing.html`. Fabricated mainnet status, star count, customer addresses, partner endorsements, and demo telemetry were removed from the rendered page. The CRE/Arc end-to-end path is explicitly labelled as not live. Vercel serves this website only; it does not deploy the Arc contracts or verifier.

## User and wallet boundary

- **Public visitor / judge:** can read and navigate the marketing page without connecting a wallet.
- **Supplier security or customer-success team:** later creates and funds an eligible campaign using an authorized supplier wallet or multisig; funding is a USDC transaction on Arc.
- **Customer protocol team / deployment owner:** later executes any repair through its own owner, multisig, or governance authority and claims a grant using the eligible recipient flow.
- **Read-only review:** should not require a wallet. Wallet connection is only needed when the future application must identify an address for an authorized write or submit a transaction.
- **Key custody:** Orynn must not collect private keys or seed phrases. A wallet or multisig signs transactions under the user's own authority.

The campaign console is not implemented by this task. Do not describe the public site as a live campaign application.
