Owner A. Base `74e904c`; result: feature commit in Git log tagged PB-12. Implemented against the exact PB-07 transparent-proxy/oracle fixture family. Other-owner B review of the upgrade route remains a shared-boundary gate; this does not claim B's financial contracts are integrated.

## Behavior and interface

`services/verifier/src/actions/repair.ts` exports `prepareRepair`, `validateRepair` and `loadRepairCompatibility`. A proposal binds deployment, source chain, manifest, snapshot, observed routing/code/configuration/authority, exact calldata/target/zero value and expiry. Separate observed EOA authorities own ProxyAdmin upgrades and customer configuration. The service reads and simulates; it never signs or sends owner transactions.

Private authenticated routes: `GET /v1/runs/:id/actions?deploymentKey=<key>` and `POST /v1/runs/:id/actions/validate` with `{deploymentKey,proposal}`. These load a caller-owned completed deployed diagnostic, validate its signed evidence against the stored scope, then freshly inspect/simulate. The request cannot supply an RPC, authority override or arbitrary operation. Unknown deployment keys return 404; stale/tampered proposals/state return 409. Per-owner action admission is bounded to 12 requests/minute in addition to existing global/IP limits.

Missing/stale compiler sources or storage layout blocks preparation. Exact V1/V2 layouts and inherited Initializable source are checked; only the approved runtime at its actual address can be upgraded to. No arbitrary initializer payload. Current code, owner and configuration drift invalidates a proposal; source price samples may change normally. Unknown governance/proxy families, source changes, ownership changes, path mismatch and paused markets require manual review.

A confirmed successful transaction is followed by a new normal diagnostic job. No action route mutates old evidence or marks a repair passed. A new run can still fail. Diagnostic proposals/results cannot qualify for a grant.

## Limits and decisions

The two supported operations are upgrade and same-source configuration. Eight decimal units are the existing supported pack's quote convention, not a user-facing arbitrary hardcoded outcome. Layout/source validation is exact-family validation, not a universal OZ upgrade-analysis replacement. Initializer payload is always empty because this reviewed V2 adds no state and requires no reinitialization.

Proposals expire within 120 seconds of the report snapshot, or earlier at scope expiry. RPC observation and simulation are point-in-time and depend on the configured RPC. Plain owner transactions have no atomic PatchBond precondition: state may change before mining. Wallet simulation plus fresh post-execution verification remain mandatory.

No campaign payout, live CRE report, CCIP delivery, hosted/testnet repair, frontend or physical second-machine proof is claimed by PB-12.
