# PB-11 — Diagnostic consumer and reproducible replay
Owner A. Consumes completed PB-04–10. API and worker are independent executable processes. Start with docs/runbooks/backend-start.md; offline replay: docs/runbooks/replay.md.

`processJob` loads immutable documents by owner/digest, checks request/scope/evaluator/source chain, selects one confirmed snapshot, follows real routes, executes the approved pack, rechecks canonicality after all scenarios, builds complete evidence and signs it. The dedicated evaluator key stays in the trusted host, outside API/container/child environments. Campaign requests remain rejected. No artifact URL or uploaded repository is executed.

`consumeNext` claims PostgreSQL leases, periodically renews, enforces a total deadline, propagates cancellation, publishes content-verified bytes, and commits only with the current live token. Cancelled/replaced workers cannot finish. A stopped/failed job is not a repair failure verdict; a succeeded job can contain failing or unknown assertions. API responses point users to the evidence instead of inventing a pass.

The sandbox has an internal process deadline as well as host-side supervision; if the worker is SIGKILLed, it cannot leave an indefinitely running container. Normal cancellation kills the client process group and explicitly removes the daemon-owned container. Captured state is validated again against the supported runtime templates before replay; a signed bundle is not permission to execute arbitrary bytecode. Market ownership is now checked against the approved customer alongside adapter configuration ownership.

Validation includes actual separate API/worker processes, real HTTP wallet login, PostgreSQL, fresh local deployments and isolated EVM execution. A worker is killed after claiming; a new worker recovers; the old token fails completion. Real passing evidence is signed, privately fetched, explicitly published and replayed through the standalone CLI. Correct code with wrong decimals produces a completed job with a signed **failed** repair result and the responsible customer address. Separate tests cover renewal, cancellation, deadline and unrecognized replay runtime. Tests use only disposable local wallets/data.

## Remaining gates
- Replayed in a fresh container and a separate CLI process on the same Mac. A different physical machine/Linux proof is still outstanding; do not mark that gate passed.
- Testnet deployments, hosted object storage, independent hosted worker/Studio callback and sponsor end-to-end evidence are not demonstrated.
- Financial receipt construction requires authoritative frozen campaign terms and eligibility; it is not enabled by signed diagnostics.
- Owner-executed repair proposals are PB-12, product CRE workflow PB-21, UI PB-24+ gate.
- API publication is explicit and irreversible in the current release. Reports include public chain state plus user-supplied issue/policy text; only the owner can choose to publish.

Independent review identified stale compiled assertion artifacts and deadline expiry during final artifact readback. Both were reproduced by failing tests. Loader now checks compiler metadata source hashes (assertion plus helper); repository completion checks cancellation after readback and enforces the absolute deadline inside the fenced SQL update. Existing migration checksums and shared Solidity vectors are unchanged. `pnpm test` builds approved fixtures before unit checks, avoiding a generated-artifact race in clean checkouts.
